# FINAL Bundle | اتاق فرمان باندلینگ توسن تکنو

برنامه PWA فارسی (راست‌چین) برای مدل باندلینگ ترکیبی: **کارتخوان** محصول هدف و **کش‌لس** محصول محرک، با هدف توسعه شبکه کارتخوان توسن تکنو.
طراحی مدل: مهدی نامدار.

- فناوری: React 19، TypeScript (Strict)، Vite، Recharts، Lucide، Vitest، vite-plugin-pwa، ESLint
- بدون Backend؛ همه محاسبات روی دستگاه کاربر انجام می‌شود و هیچ داده‌ای ارسال یا ذخیره نمی‌شود.

## پیش‌نیازها

Node.js نسخه ۲۰ یا بالاتر و npm.

## نصب و اجرا

```bash
npm install            # نصب وابستگی‌ها
npm run dev            # اجرای توسعه (قبل از آن npm run brand خودکار اجرا می‌شود)
npm test               # تست‌های Vitest برای منطق مالی
npm run lint           # ESLint
npm run typecheck      # بررسی TypeScript
npm run build          # ساخت Production در پوشه dist (شامل Service Worker)
npm run preview        # پیش‌نمایش Build؛ PWA را فقط روی این نسخه یا نسخه منتشرشده بررسی کنید
```

## لوگوی توسن تکنو و فونت یکان

برنامه عمداً هیچ لوگو یا فونتی را جعل نمی‌کند. تا وقتی فایل‌های رسمی نباشند:
در سربرگ و Splash یک آیکون خنثی نمایش داده می‌شود و فونت Vazirmatn (بسته‌شده محلی) و سپس Tahoma استفاده می‌شود.

۱. **لوگو**: فایل را با یکی از نام‌های `logo.svg` (ترجیحاً)، `logo.png` یا `logo.webp` در `public/brand/` بگذارید.
۲. **یکان**: فایل‌های **دارای مجوز** را با نام‌های `Yekan-Regular.woff2` (وزن ۴۰۰) و در صورت وجود `Yekan-Bold.woff2` (وزن ۷۰۰) در `public/fonts/` بگذارید (`.woff` و `.ttf` هم پذیرفته می‌شوند).
۳. دستور `npm run brand` را اجرا کنید (قبل از `dev` و `build` خودکار اجرا می‌شود).

نتیجه: لوگو در Splash و سربرگ نمایش داده می‌شود، آیکون‌های PWA (۱۹۲، ۵۱۲، maskable و apple-touch) از روی آن ساخته می‌شوند و `@font-face` یکان تولید می‌شود. فونت یکان در ابتدای `--font` قرار دارد و در صورت نبود فایل، به‌طور خودکار به Vazirmatn می‌رسد.

## مدل مالی

همه مبالغ بر حسب میلیون تومان‌اند. فرمول‌ها فقط در `src/features/bundle/bundle.calculator.ts` پیاده شده‌اند و UI فرمول مستقلی ندارد. محاسبه روی «هزار تومان» صحیح انجام می‌شود تا خطای اعشاری پیش نیاید؛ گردکردن فقط هنگام نمایش است.

| شاخص | فرمول |
|---|---|
| مرجع اقتصادی کارتخوان | قیمت پایه + بودجه بازاریابی کارخانه |
| تعدیل هر کارتخوان | max(۰، مرجع − قیمت هدف) |
| تعدیل کل | تعدیل هر کارتخوان × تعداد کارتخوان |
| بودجه هر کش‌لس | قیمت فروش − هزینه تمام‌شده − حاشیه سود هدف |
| بودجه اولیه باندلینگ | بودجه هر کش‌لس × تعداد کش‌لس |
| مانده بودجه | بودجه اولیه − تعدیل کل |
| حاشیه سود هدف کل | حاشیه سود هدف × تعداد کش‌لس |
| مانده اقتصادی نهایی | مانده بودجه + حاشیه سود هدف کل |
| قیمت تخصیصی واقعی کش‌لس | هزینه تمام‌شده + مانده اقتصادی نهایی ÷ تعداد کش‌لس (فقط اگر تعداد کش‌لس > ۰) |
| ارزش فروش اسمی بسته | قیمت هدف کارتخوان × تعداد کارتخوان + قیمت فروش کش‌لس × تعداد کش‌لس |
| سهم‌های نمودار | بخش مثبت ÷ (مانده مثبت + حاشیه مثبت)؛ مخرج صفر ⇒ ۰٪ |

مقادیر پیش‌فرض (۱۰ کارتخوان، ۱۰ کش‌لس، ۱۹، ۱۵، ۱، ۲۵، ۴۲، ۲) این نتایج را می‌دهند: مرجع ۲۰، تعدیل هر دستگاه ۵، تعدیل کل ۵۰، بودجه اولیه ۱۵۰، مانده ۱۰۰، حاشیه هدف ۲۰، مانده نهایی ۱۲۰، قیمت تخصیصی ۳۷، ارزش اسمی ۵۷۰ — و تست‌ها همین را بررسی می‌کنند.

### محدودیت‌های محاسبه سود

- بودجه بازاریابی کارخانه فقط یک‌بار، در مرجع اقتصادی کارتخوان، لحاظ می‌شود و دوباره از بودجه کش‌لس کم نمی‌شود.
- **حاشیه سود هدف سود تحقق‌یافته نیست** و قیمت پایه کارتخوان لزوماً بهای تمام‌شده آن نیست. برنامه سود خالص محاسبه یا ادعا نمی‌کند.
- «قیمت تخصیصی واقعی کش‌لس» شاخص تخصیص مدیریتی است، نه قیمت فروش ثبت‌شده.
- مانده بودجه منفی ⇒ «نیازمند اصلاح (کسری بودجه)»؛ نمودار نمایش داده نمی‌شود و سناریوی دارای کسری هرگز به‌عنوان مدل تأییدشده یا پیشنهاد نماینده دیده نمی‌شود.

### اعتبارسنجی

تعداد‌ها عدد صحیح ≥ ۱؛ تعداد کش‌لس ≤ تعداد کارتخوان؛ مبالغ غیرمنفی؛ قیمت فروش کش‌لس ≥ هزینه + حاشیه هدف. ورودی خالی یا غیرعددی (با پشتیبانی از ارقام فارسی و عربی) خطای کنار فیلد می‌دهد و برنامه Crash نمی‌کند. قیمت هدف بالاتر از قیمت پایه هشدار می‌دهد و بالاتر از مرجع اقتصادی، تعدیل را صفر می‌گیرد.

## مدل‌های تجاری (بسته شاپرکی، ترکیبی، شتابی)

هیچ عدد یا قاعده تجاری تأییدشده‌ای برای تعداد/قیمت این سه مدل وجود ندارد، بنابراین موتور سناریو (`bundle.presets.ts`) آن‌ها را از دو **پارامتر قابل تنظیم** می‌سازد و سیاست قطعی توسن تکنو نیستند:

۱. سهم کش‌لس از کل سبد (٪) — پیش‌فرض‌های ابتدایی ۳۰، ۴۰ و ۵۰ فقط نقطه شروع‌اند (`DEFAULT_SCENARIO_RULES`)؛ کل سبد = تعداد کارتخوان + تعداد کش‌لس مدل جاری.
۲. قیمت هدف کارتخوان (خالی = قیمت هدف مدل جاری).

هر سناریو با همان اعتبارسنجی و فرمول‌های مدل پایه ارزیابی می‌شود. سناریوها رتبه‌بندی نمی‌شوند.

## نمای مدیریتی و نمای شبکه فروش

کنترل بالای صفحه بین دو نما جابه‌جا می‌شود. نمای شبکه فروش فقط نام بسته، تعداد‌ها، قیمت‌های پیشنهادی، ارزش اسمی و مزایای تجاری (محاسبه‌شده از داده جاری) را نشان می‌دهد و فقط بسته‌های معتبر و بدون کسری را دارد.

> **هشدار:** این جداسازی **نمایشی** است، نه کنترل امنیتی. برنامه کاملاً سمت کاربر اجرا می‌شود، ورود کاربر یا مجوز ندارد و تمام کد و فرمول‌ها در بسته جاوااسکریپت ارسالی به مرورگر هستند. اگر محرمانگی واقعی لازم است، باید احراز هویت و API سمت سرور اضافه شود.

## خروجی‌ها

- **CSV**: UTF-8 همراه BOM، ستون‌های فارسی. نام فایل‌ها `FINAL-Bundle-report.csv` (مدیریتی) و `FINAL-Bundle-agent-offers.csv` (نماینده). گزارش نماینده هیچ داده داخلی ندارد. با ورودی نامعتبر، خروجی غیرفعال است.
- **PDF**: دکمه «چاپ / ذخیره PDF» صفحه را با CSS چاپ A4 آماده می‌کند؛ در پنجره چاپ مرورگر «Save as PDF» را انتخاب کنید. دکمه‌ها و کنترل‌ها در چاپ حذف می‌شوند و تاریخ و وضعیت اعتبار در سربرگ چاپ می‌آید.

## Splash

دقیقاً ۱۰ ثانیه نمایش داده می‌شود. نشانه «دیده‌شده» فقط در `sessionStorage` (برای همان نشست) نگه داشته می‌شود و remount شدن کامپوننت شمارش را از نو شروع نمی‌کند. هیچ داده مالی در localStorage/IndexedDB ذخیره نمی‌شود؛ با بستن یا Refresh صفحه ورودی‌ها به پیش‌فرض برمی‌گردند.

## PWA

- Manifest و Service Worker با `vite-plugin-pwa` (حالت `prompt`): نسخه جدید فقط با تأیید کاربر فعال می‌شود و کش قدیمی پاک می‌شود (`cleanupOutdatedCaches`).
- همه فایل‌های Build (JS، CSS، HTML، آیکون، فونت) پیش‌کش می‌شوند؛ به CDN وابستگی نیست و محاسبات پس از اولین بارگذاری موفق آفلاین کار می‌کنند.
- دکمه «نصب برنامه» فقط وقتی مرورگر رویداد نصب را بفرستد نمایش داده می‌شود؛ در iOS راهنمای Add to Home Screen نشان داده می‌شود.
- بررسی: `npm run build && npm run preview`، سپس DevTools ← Application ← Manifest / Service Workers؛ بعد Network را Offline کنید و صفحه را Refresh کنید.

### نصب

- **iPhone**: آدرس HTTPS را در Safari باز کنید ← Share ← Add to Home Screen ← Add.
- **Android**: در Chrome گزینه Install app یا Add to Home screen (نام دقیق بسته به نسخه متفاوت است).
- **دسکتاپ**: در مرورگر پشتیبانی‌شده از دکمه Install در نوار آدرس یا منوی مرورگر.

## استقرار

### Vercel

```bash
npm install
npm run build          # باید بدون خطا تمام شود
npx vercel             # Preview (نیازمند ورود به حساب Vercel)
npx vercel --prod      # Production
```

`vercel.json` آماده است: خروجی `dist`، بدون Cache برای `sw.js`، `registerSW.js`، `manifest.webmanifest` و `index.html` و Cache طولانی برای `/assets/*`. Rewrite عمومی عمداً وجود ندارد تا Manifest و Service Worker به HTML تبدیل نشوند؛ برنامه تک‌صفحه‌ای است و مسیر داخلی ندارد.

### هاست HTTPS

محتوای `dist/` را روی هر هاست استاتیک با **HTTPS** بگذارید. برای `sw.js` و `index.html` هدر `Cache-Control: no-cache` تنظیم کنید و `manifest.webmanifest` را با نوع `application/manifest+json` سرو کنید. نصب PWA بدون HTTPS ممکن نیست (به‌جز `localhost`).

## تغییر مقادیر پیش‌فرض، آیکون و فونت

- مقادیر پیش‌فرض مدل: `src/features/bundle/bundle.defaults.ts`
- قاعده‌های سناریو: `DEFAULT_SCENARIO_RULES` در `src/features/bundle/bundle.presets.ts`
- آیکون: لوگو را در `public/brand/` بگذارید (آیکون‌های PNG خودکار ساخته می‌شوند)؛ آیکون پیش‌فرض خنثی `public/icon.svg` است.
- فونت: بخش «لوگوی توسن تکنو و فونت یکان» بالا؛ ترتیب فونت‌ها در `--font` فایل `src/styles/global.css`.
